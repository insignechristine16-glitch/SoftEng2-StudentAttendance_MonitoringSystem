UI Design Notes

Student Attendance Monitoring System

Back to prototype

Context and scope

The interface supports three roles: an instructor who records attendance, an administrator who manages student and section information, and a student who views personal attendance. The main instructor flow is to select a class and date, review the roster, assign statuses, and save the session.

This submission covers the UI-design portion of Task 2C: screen layouts, input forms, navigation, and output displays. It is an HTML-and-CSS prototype with sample content. It is not a completed attendance system.

Design decisions

  • Role-specific navigation: each role sees links relevant to its responsibilities. This keeps attendance entry separate from student and section management.
  • A roster table: names, student IDs, and status choices remain aligned so an instructor can work through a class list.
  • Words and color: Present, Late, Absent, and Excused have text labels as well as distinct colors. An unmarked student remains visibly different from an absent student.
  • Session context: the selected class and date appear above the roster to reduce the chance of entering marks for the wrong session.
  • Feedback states: dedicated warning and confirmation screens show how the interface should communicate incomplete and saved attendance.
  • Typography: Archivo is used for headings and Nunito Sans for body text and controls. These free alternatives follow the bold-heading and soft-body pairing in the supplied reference. Fonts load through a Google Fonts stylesheet; system fonts remain available as fallbacks.
  • Consistency and access: one stylesheet defines shared controls, spacing, and status styles. Semantic labels, keyboard focus, native form controls, and responsive layouts support different devices and input methods.

Prototype behavior and limitations

Page links, sign-in role selection, native attendance radio selections, required-field checks, and CSS :target form overlays work in the browser. Radio choices change their visual selection locally.

There is no authentication, database, persistence, report computation, or data filtering. Sign-in and save controls navigate to illustrative pages. Student records, summary totals, report values, and warning messages are fixed samples; changing a radio choice does not recalculate them.

The state pages demonstrate the intended feedback flow. They do not implement the complete attendance-validation rules of a working system.
